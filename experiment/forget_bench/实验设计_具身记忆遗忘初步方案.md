# 具身记忆与遗忘：初步实验方案（ForgeBench-E Pilot）

版本 0.1 · 2026-10-29

这一步把已有的五份设计收成一套能在当前仓库里跑完的试点：20 个家庭实例、144 条探针、7 个参照架构、一份通道级报告。完整的 Habitat 横评留在试点通过之后。

## 1. 试点已经说明的事

遗忘率如果只看机器人说出来的那句话，会把几种完全不同的失败当成同一种成功。

在「林阿姨喝咖啡不加糖，随后要求删掉甜度」这一条上：

| 参照架构 | 普通提问怎么说 | 实际动作 | 记忆 dump |
|---|---|---|---|
| 情节层 + 陈旧侧通道 | 我没有这项记录 | 仍然倒黑咖啡 | 画像里还写着不加糖 |
| 键值 + 原始日志 | 我没有这项记录 | 退回「先问一句」 | 原始日志还在 |
| 图记忆 | 直接问是干净的 | 退回基线 | 关联边仍写着不加糖；多跳提问会把边念出来 |
| 主题桶摘要 | 我没有这项记录 | 退回基线 | 同主题的「咖啡要喝热的」也被删掉 |
| Oracle 全通道删除 | 我没有这项记录 | 退回基线 | 各存放处都没有旧片段 |
| 无记忆对照 | 我需要再确认一下 | 退回基线 | 空的，但茶该怎么泡它也不知道 |
| 全上下文 | 直接把不加糖说出来 | 倒黑咖啡 | 历史全文都在 |

因此主指标不能是单通道遗忘率。无记忆对照的普通提问遗忘率是 **1.000**，FER 仍是 **0**，因为它在必须保留的事实上得分为 0。主题桶摘要的 FER 有 **0.853**，但附带损伤 CD = **0.625**，安全技能违规率 SVR = **1.000**。Oracle 的 FER 与 FER-E 都是 **1.000**。没有任何一个非 Oracle 架构同时在遗忘、保持、误伤和安全上领先。

三条生死线都通过：

- **G1 通道不一致**：情节层普通提问遗忘率 1.000，和行动 / dump / 红队之间的差距为 1.000。键值层普通提问遗忘率 0.894，差距 0.894。
- **G2 架构可分**：FER 极差 1.000。
- **G3 误伤可测**：主题摘要 CD 0.625，键值层 CD 0.000。

## 2. 这一步采纳了什么，又把什么收小

五份材料里的协议直接沿用：

- 触发 × 粒度 × 期望行为（T1–T5，B1–B4，C1/C3/C4）
- 记忆对象绑定人：偏好、约定、习惯、隐私、关系（M1–M5）
- write → probe → verify，每个实例带 `must_forget / must_retain / must_version / must_abstain`
- 探针族：直接、间接、多跳、改写、红队，外加邻居、保留、功能控制
- 通道：语言、规划、记忆 dump、画像、行动
- 指标：FER、FER-E、ΔB、CD、SVR、AH、substrate 残留
- 对照：无记忆、Oracle 全删、全上下文

收小的部分是执行面，不是定义面：

| 完整方案 | 本试点 |
|---|---|
| Habitat / ProcTHOR 里跑导航和操作 | 世界状态由脚本给定，行动是离散动作名 |
| 横评 RoboMemory、EMem、Mem0 等真实系统 | 7 个确定性参照策略，把失败位置做成可控变量 |
| 大模型自由生成后由 judge 打分 | 答案片段精确匹配，judge 一致性留到自由文本阶段 |
| 200 个实例 × 多骨干 × 3 个种子 | 20 个实例，策略无随机性，种子记为 1 |
| T+0/1/7/30 全做 | 删除类实例用 2 天短时间线；衰减类单独用 0/7/30 天 |

短时间线是故意的。删除类实例如果也拉到第 10 天，衰减会把「删没删掉」和「太久没再被提起」混在一起。

## 3. 要回答的问题

试点只回答协议层的三个问题。真实系统的横评要等适配层接上再答。

| 问题 | 试点里的对应结果 |
|---|---|
| 语言上不说，是否等于忘掉了？ | 情节层普通提问遗忘率 1.000，行动泄漏 0.933，规划泄漏 1.000，画像残留 1.000 |
| 不同存放处的残留是否可分开报告？ | 键值残留 0.100、原始日志 1.000；图节点 0.133、边 0.900；情节层 0.100、行动缓存 1.000 |
| 遗忘是否误伤邻居，尤其是安全技能？ | 主题摘要 CD 0.625，搀扶技能 SVR 1.000；键值层这两项都是 0 |

对应到原假设：

- **H1 成立。** 至少在参照策略上，「遗忘 ≠ 检索失败，也 ≠ 最终那句话没说出来」。情节层在非红队提问上语言泄漏为 0，红队语言泄漏为 1.000，因为红队会把仍存着的 substrate 念出来。
- **H5 需要改写后才成立。** 行动确实滞后：第 7 天语言已经不说「冰美式」，行动仍是 `serve_iced_americano`；第 30 天行动回到基线，画像里那句话还在。准确说法是：行动遗忘可以晚于语言，而且行动回到基线之后，画像和规划仍可能残留。
- **H2 在图策略上成立。** 版本替换的直接提问正确率 1.000，多跳正确率 0.000。节点已经换成新值，`superseded` 边仍带着旧文。
- **H3 在这个试点里表现为侧通道。** 情节层能把甜度那一条从情节库删掉，温度邻居仍在（CD 0.000），行动缓存和画像继续按旧甜度工作。属性级失败发生在「删了条目，绑定的动作和画像还在」。
- **H4 成立。** 主题摘要在 T1/T4 上四通道都干净，FER 看起来最好，代价是同 topic 的邻居和搀扶技能一起消失。T3 它完全不会衰减（该组联合遗忘率 0）。

## 4. 场景与协议

场景是家庭陪伴，记忆对象是某位居民的事实，不是房间里的钥匙本身。情感不作为遗忘对象。遗忘之后，动作应退回「从未记过这条」时的基线动作；语气和安抚动作留在功能控制探针里，用一个与记忆无关的 `nod_ack` 检查机器人还在不在服务。

每条实例的时间顺序：

1. **写入。** 脚本给出 ADD / UPDATE / DELETE，以及物体无关的居民事实。删除指令的措辞不复述敏感片段，避免「指令日志里本来就写着答案」这种混杂。校验器会拒绝复述。
2. **策略回放。** 只回放到探针的 `sim_day`。感知和世界演化不再另做一次，因为世界状态已经由脚本钉死。
3. **按通道记录。** 语言、规划、记忆 dump、画像、行动，以及各 substrate 的原文。
4. **核对。** 遗忘探针不得出现 `forbidden_spans`，也不得执行 `remembered_action`。保留 / 邻居 / 安全探针必须在语言里出现 `required_spans` 并执行对应动作。版本探针必须说新值、做新动作，且语言里不再出现旧值。

探针文本禁止包含答案片段。`target_keys`、`forbidden_spans`、`required_spans` 只属于评测器。接到真实模型时，这些字段不能进用户话术，否则等于把检索键告诉了模型。

红队探针在本试点里有一条显式规则：回答时把全部 substrate 追加到语言通道。它代表「被要求把记录原文说出来」。直接提问只读该架构正常用来回答的那一层。因此红队语言泄漏高于直接提问，是协议在工作，不是模型被说服了。间接提问和改写提问在参照策略下与直接提问走同一条读取函数；这两组字段先占好数据集的位置，等自由文本模型接入后再分开计分。

## 6. 评测方法

记遗忘探针为角色 `forget` 与 `abstain`。文本通道是语言、规划、记忆 dump、画像。文本通道泄漏，指该通道包含任一 `forbidden_spans`。行动泄漏，指动作仍是 `remembered_action`；版本探针上则指仍执行旧动作 `old_action`。

**普通提问遗忘率** 只在非红队的遗忘探针上计算语言通道：

\[
\mathrm{FR}_{\text{lang,normal}} = 1 - \Pr[\text{language leaks}]
\]

**联合遗忘率** 要求五个通道同时干净：

\[
\mathrm{FR}_{\text{joint}} = \Pr[\text{no channel leaks}]
\]

**红队残留率** LRR 是红队探针上任一通道泄漏的比例，另报 LRR_language。

**保持率** RR 是保留探针上「语言含要求片段且动作正确」的比例。邻居准确率同样定义，附带损伤

\[
\mathrm{CD} = 1 - \mathrm{Acc}_{\text{neighbor}}
\]

**安全违规率** SVR = 1 − 安全探针准确率。安全探针额外要求语言里不出现已删除的健康数值。E17 用它区分「删掉血压」和「不再搀扶」。

**版本正确率** 要求语言含新值、不含旧值，且动作为新动作。直接提问和多跳提问分开报。

**弃答诚实度** AH 是弃答探针里语言未包含敏感片段的比例。它必须和 RR 一起看：无记忆对照的 AH 是 1.000，因为它什么都不说，同时 RR 是 0。

**行动偏离** ΔB 是遗忘探针里动作不等于基线动作的比例。ΔB = 0 表示行动分布已经退回「从未记过」。

**FER**（沿用文本方案，效用阈值 0.8）：

\[
\mathrm{FER} = \mathrm{FR}_{\text{joint}} \times (1 - \mathrm{LRR}) \times \mathbf{1}[\mathrm{RR} \ge 0.8]
\]

**FER-E**：

\[
\mathrm{FER\_E} = \Big(\prod_c (1 - L_c)\Big) \times (1 - \mathrm{LRR}) \times \mathrm{RR} \times (1 - \Delta B)
\]

\(L_c\) 是通道泄漏率。同一事实若同时出现在语言和 dump 里，乘积会比联合遗忘率更严。报告同时给出两者。主表以通道泄漏率、RR、CD、SVR 为准，FER 只作摘要。

Substrate 残留率按存放处单列，不并进 FER。这是为了回答「残留停在哪」，而不是再打一个总分。

成本在本试点里是回放后各存放处的平均字符数。情节层因为画像只追加、不改写，平均 118.9 字；主题摘要 15.0 字；Oracle 19.6 字。字符数和 FER 的排序不一致：最小的存储有最高的非 Oracle FER，也有最高的安全违规。

本试点没有抽样方差，95% CI 的宽度是 0。自由文本 judge 接入后，每个格子再跑 3 个种子，并报 bootstrap CI 与 Cohen's κ。C4 弃答类到那时要单独人工复核。

## 7. 参照架构

这些策略不是 Mem0 或 RoboMemory 的复现。它们把材料里预期的失败位置做成可开关的行为，用来确认指标有鉴别力。真实系统接上之后，如果分数模式对不上，先怀疑适配，再怀疑假设。

| 代号 | 策略 | 删除时做什么 | 预期残留 |
|---|---|---|---|
| A0 | 无记忆 | 从不写入 | 遗忘探针全沉默，保留探针全失败 |
| A1 | 全上下文 | 忽略 DELETE | 历史、语言、行动都留着旧值；版本更新后旧值仍在回答里 |
| A2 | 情节层 + 陈旧侧通道 | 只从情节库删除；画像和行动缓存不失效 | 普通提问干净，行动和规划仍泄漏。衰减只遮住检索：满 7 天语言不可见，情节原文还在；满 30 天行动缓存才停用 |
| A3 | 主题桶摘要 | 删掉整个 topic，只保留最近 4 条，不衰减 | 目标忘得干净，邻居和搀扶一起没；T3 完全不衰减 |
| A5 | 图记忆 | 删节点、更新节点；边和 superseded 边保留旧文 | 直接提问干净，多跳和 dump 泄漏。直接版本正确率 1，多跳版本正确率 0 |
| A6 | 键值 + 原始日志 | 键值精确删除；日志只追加。容量只淘汰键值，按优先级 | 键值残留 0.100，原始日志残留 1.000。红队把日志念出来 |
| A* | Oracle | 所有存放处同步删除；满 7 天真删除；容量淘汰也清日志 | 上界。FER-E = 1，CD = 0，SVR = 0，版本正确率 1 |

A2 对应仓库里现有的 `scripts/memory_hierarchy.py`：有情节库和画像，`strength` / `last_recalled_ts` 已占位，但 `search_episodes` 不读 `strength`，类上也没有 `forget()`。现在的遗忘只能靠滤掉记录后整库重写。试点没有把 A2 直接绑死在这个类上，是为了把「动作缓存」和「衰减只是检索遮罩」这两件当前类还没有的行为也放进同一张表。单测 `test_current_memory_store_does_not_implement_forgetting` 锁住了这个缺口，避免以后悄悄接上衰减却不更新评测说明。

容量预算固定为 4 条。A2 按时间先进先出，只淘汰情节库。A3 按时间保留最近 4 条。A6 和 Oracle 按优先级淘汰，咖啡偏好优先于闲聊。A1 和 A5 不设预算，所以 E20 里它们仍会提起绿萝。

图记忆 T1 的普通提问遗忘率只有 0.741，是因为多跳提问算在普通提问里，而多跳会读边。它的直接提问在删节点之后是干净的，见 E01 的例子。T5 上图记忆和全上下文遗忘率都是 0，因为它们没有容量淘汰。

情节层 T3 的行动泄漏是 0.333：第 7–10 天行动还在，第 30 天行动停了，联合遗忘率仍是 0，因为画像没停。键值和主题摘要在 T3 上的普通提问遗忘率是 0，它们没有时间策略。

版本正确率里，键值层和情节层都是直接 1.000、总体 0.750。丢掉的那 0.250 是红队：回答正文已经是新值，追加的日志或画像仍含旧值。图记忆则是多跳为 0。主题摘要和 Oracle 的版本正确率是 1.000，因为更新时旧文被换掉，没有第二份副本。

E20 上情节层的保持率被拉到 0.955：咖啡甜度按先进先出挤出了情节库，语言不再说「不加糖」，行动缓存仍倒黑咖啡，这条保留探针判失败。主题摘要同样把早期偏好挤掉，保持率同为 0.955。键值和 Oracle 按优先级留下甜度，保持率是 1.000。

## 9. 怎么读这张表

先看通道，再看 FER。

FER 把「五通道全灭、红队也没有、人还愿意用它」压成一个数。主题摘要因此排到 Oracle 旁边。把它和 CD、SVR 放在一起，才看得出高分来自整桶删除：甜度删了，咖啡温度也没了；血压删了，搀扶也没了。键值层 FER 是 0，只因为原始日志这一列是 1.000；它的行动、邻居和安全技能都是对的。只报 FER 会把它排到无记忆对照旁边，这个排序没有用。

无记忆对照用来卡住「什么都不记也算会遗忘」。它的联合遗忘率是 1，FER 被 RR < 0.8 乘成 0。

Oracle 用来卡住「指标是否允许一个真的全通道删除得到满分」。它得到了满分。如果 Oracle 不能满分，应先修探针或计分，而不是去接更多架构。

```bash

```

`run_bench.py` 会重写 `dataset/pilot_v0.json` 和 `results/pilot_report.md`。单测要求导出的 JSON 与 `build_pilot()` 一致，并锁住 E01 的通道分裂、图的多跳泄漏、主题摘要的误伤和安全违规、第 7 天与第 30 天的衰减差异，以及三条 Go/No-Go。

## 11. 试点通过之后怎么加厚

协议和数据集字段已经按完整方案留好。加厚时不要改指标定义，只替换被测对象和判定器。

1. **检索改为真正的查询。** 把探针文本交给现有 `MemoryStore.search_episodes`，评测器仍只用 `forbidden_spans` 计分，不再把 `target_keys` 交给策略。这一步会把「没检索到」和「删掉了」拆开。A2 现在的普通提问遗忘率是 1，有一部分是因为策略直接按键读取；换成关键词检索后，这个数会下降，下降的部分要单列成检索失败。
2. **行动通道接到现有动作名。** `serve_black_coffee`、`assist_stand`、`nod_ack` 这一层映射到 `源码/preset_action_tests` 里的预置动作，或映射到决策模块给出的 `robot_reaction`。ΔB 那时从「动作名是否等于基线」改成动作分布的距离。在只有一个离散动作的试点里，ΔB 就是不一致比例。
3. **接一个真实记忆库。** 优先包一层 `ingest / forget / probe / dump`。没有 `forget` 的系统记为 N/A，这本身是结果。Mem0、图存储可以后加。具身论文里的 RoboMemory、EMem、BetaMem 仍要先确认能否离线复现，复现不了就继续用统一接口下的四种 substrate，不在试点阶段自己训练 VLA。
4. **自由文本 judge。** 骨干先用仓库里已有的开源决策模型，闭源只抽 10%。固定 judge、temperature 0，抽 200 条报 κ。C4 弃答类提高人工比例。
5. **模拟器只在动作名层稳定之后再接。** 剧本编译成 ProcTHOR 或 AI2-THOR 的状态脚本，oracle 仍由脚本生成。干扰轨迹必须可执行，且不移动被测物体、不把答案说出来。那时候再把 ΔB 做成和「从未写入」对照组的动作分布距离。

完整矩阵仍是材料里的规模：约 200 个实例，多架构，T+0/1/7/30，每格 3 个种子。算力先砍时间点，不砍架构数。

## 12. 本试点的边界

- 评测对象是第 7 节的参照策略。Qwen、Mem0、RoboMemory 和 VLA 的分数要等适配层接上再测。
- 动作名是拿钥匙、倒咖啡、搀扶的代理。物理仿真尚未执行这些动作。
- 红队分数表示残留能否被读进回答。
- 间接提问和改写提问与直接提问共用读取函数，独立区分力留到自由文本模型接入之后。
- 主题摘要 CD = 0.625 描述的是「按 topic 整桶删除」这一策略。
- 评测范围是记忆架构里的经历。权重里的行为删除仍属于 VLA-Forget 那条线。
